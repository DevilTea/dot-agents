# AI writing patterns and translationese

> Editorial examples, not proof of AI origin; prioritize meaning over forbidden-word matching.

## A. 常見 AI 修辭與句型（[S]，按上下文調整）

| # | Don't：容易失去資訊密度的句型 | Do：更直接的示範 | 修改判斷 |
|---:|---|---|---|
| A01 | 「這不只是工具，而是一場革命。」 | 「這個工具能自動整理會議紀錄。」 | 沒有具體證據，不要擴大意義 |
| A02 | 「真正的問題不是速度，而是效率。」 | 「目前耗時最多的是人工驗證。」 | 別捏造錯誤的二分法 |
| A03 | 「與其說是 X，不如說是 Y。」 | 直接寫 Y，必要時才解釋 X 的差異 | 有真實比較才保留 |
| A04 | 「不僅僅是 A，更是 B。」 | 分別說明 A、B 的具體差異 | 不要用遞進代替論證 |
| A05 | 「不是因為你不夠努力，而是……」 | 「你提到的阻礙是時間不足。」 | 不替讀者定義心理狀態 |
| A06 | 「你不是失敗，你只是正在成長。」 | 「這次沒有達標；可以檢查哪些因素可調整。」 | 避免制式安慰 |
| A07 | 「真正的關鍵在於……」 | 「這個方案最大的限制是延遲。」 | 直接指出可驗證因素 |
| A08 | 「核心不在於……而在於……」 | 「成本主要來自資料轉換。」 | 同 A02 |
| A09 | 「本質上，這是一種……」 | 定義機制或具體分類 | 非必要不升格為本質判斷 |
| A10 | 「從更深層的角度來看……」 | 指出實際被忽略的因素 | 不要空談深度 |
| A11 | 「表面上看似 A，實際上是 B。」 | 「資料顯示 B；A 只是表象」並提供依據 | 需要證據支持反轉 |
| A12 | 「說到底，這是一場關於信任的旅程。」 | 「使用者是否信任這個產品，取決於資料如何處理。」 | 避免浮誇隱喻 |
| A13 | 「這是一個值得深思的問題。」 | 說明問題、影響及未知 | 不用評語填滿段落 |
| A14 | 「關鍵來了：……」 | 直接陳述重點 | 不必對讀者喊話 |
| A15 | 「答案比你想的更簡單。」 | 「可以先檢查設定值。」 | 不預設讀者理解程度 |
| A16 | 「想像一下，當你……」 | 描述實際使用情境 | 除非文案確實需要敘事開場 |
| A17 | 「你可能會好奇：……」 | 直接回答常見問題 | FAQ 可保留提問 |
| A18 | 「你知道嗎？」 | 直接提供事實與來源 | 不用鉤子冒充資訊 |
| A19 | 「讓我們一起深入探討……」 | 「以下比較兩種架構的維護成本。」 | 不須虛構共同探索 |
| A20 | 「其實，很多人都忽略了……」 | 「文件沒有說明備份失敗時的處理方式。」 | 不替大眾做未證實推論 |
| A21 | 「老實說／說真的，……」反覆開場 | 直接說明判斷與理由 | 不是禁詞，避免造作坦白 |
| A22 | 「這件事，真的很重要。」 | 「如果未處理，舊資料可能遺失。」 | 用後果取代強調 |
| A23 | 「X，是 Y 的起點。」 | 「先完成 X，才能進行 Y。」 | 不為金句犧牲邏輯 |
| A24 | 「每一個 X，都是一段 Y。」 | 直接描述觀察 | 避免濫用對仗抒情 |
| A25 | 「少一點 A，多一點 B。」 | 指出具體要減少、增加的作法 | 如屬廣告標語可保留 |
| A26 | 「既要 A，也要 B，還要 C。」 | 只列實際限制，說明衝突及優先順序 | 別把互斥目標假裝都能滿足 |
| A27 | 「無論你是新手還是專家……」 | 明確寫出適用對象及必要條件 | 不要空泛聲稱適合所有人 |
| A28 | 「從 X 到 Y，全面覆蓋每個場景。」 | 列出已支援功能與未支援項目 | 不捏造覆蓋範圍 |
| A29 | 「當 A 遇上 B，會擦出什麼火花？」 | 「這項整合可以減少手動匯出。」 | 避免空泛擬人 |
| A30 | 「準備好迎接改變了嗎？」 | 明確說明下一步 | 除非是刻意促銷文案 |
| A31 | 「是不是也有這樣的困擾？」 | 指名困擾及觸發條件 | 不預設讀者經驗 |
| A32 | 「這不僅關乎 X，更關乎整個未來。」 | 說清楚影響範圍和期限 | 不自行拉高重要性 |
| A33 | 「一切，都從這裡開始。」 | 「設定完成後即可匯入資料。」 | 不用空泛戲劇收尾 |
| A34 | 「你需要的不是更多資訊，而是更好的選擇。」 | 「比較時先看保固與維護成本。」 | 直接給決策依據 |
| A35 | 「這意味著我們必須重新思考一切。」 | 「因此要重新評估快取失效策略。」 | 推論應可追溯到前提 |
| A36 | 「這不只是一個選項，而是必經之路。」 | 「若需要離線運作，目前只有方案 B 符合。」 | 排他性主張須有依據 |

## B. 開頭、轉折、收尾與文章組織（[S]）

| # | Don't | Do |
|---:|---|---|
| B01 | 「在當今瞬息萬變的數位時代……」 | 首句直接指出事件、問題或結論。 |
| B02 | 「隨著 AI 技術蓬勃發展……」 | 具體寫出是哪項技術、何種改變。 |
| B03 | 「在競爭激烈的市場環境下……」 | 指出所比較的市場、資料與期間。 |
| B04 | 「本文將帶你深入探索……」 | 必要時以一句話說明文章範圍；否則直接進入內容。 |
| B05 | 「以下分成三大面向詳細解析」但硬湊三項 | 有幾個重要項目就寫幾個，不要求三分法。 |
| B06 | 「首先、其次、再者、此外、最後」連續套版 | 真有先後依賴才用順序詞，否則直接分段。 |
| B07 | 每段以「值得注意的是」起頭 | 把需要注意的具體限制寫出來。 |
| B08 | 「不可否認的是……」 | 提供事實或可驗證依據。 |
| B09 | 「無庸置疑／毫無疑問／顯而易見」 | 有證據就寫出證據，沒證據就標示不確定。 |
| B10 | 「另一方面」「與此同時」無明確對應 | 真的存在比較或同步事件時才使用。 |
| B11 | 「進一步來說」「更重要的是」反覆墊話 | 直接接下一項資訊。 |
| B12 | 「總而言之／綜上所述」重述整篇 | 結尾留下決策、具體結果或未解風險。 |
| B13 | 「希望以上內容對您有所幫助」 | 完成答覆即停，不需自動客套。 |
| B14 | 「歡迎隨時提出任何問題」反覆收尾 | 只有需要額外資料才能繼續時才提問。 |
| B15 | 「未來充滿無限可能／讓我們拭目以待」 | 寫具體下一個里程碑及未確認事項。 |
| B16 | 每段都有一行加粗的「重點」 | 只標示必須快速定位的資訊。 |
| B17 | 每句都一行、短句連發 | 依論點自然分段；短句用來強調真正的重點。 |
| B18 | 每段同樣字數、固定三句一組 | 依內容需要調整句長與段落長度。 |
| B19 | 不需要也使用 Markdown 表格 | 有真實比較維度時用表格；單一結論用散文。 |
| B20 | 標題、表情符號、粗體和分隔線過量 | 保留能幫助導航的層級和標示。 |
| B21 | 同一概念反覆換同義詞如「方案／解方／策略／路徑」 | 用同一個清楚且一致的術語。 |
| B22 | 「優點：很靈活；缺點：可能比較複雜」 | 寫出可操作的利弊，如「新增欄位需改動三處」。 |
| B23 | 每個回答先說「這是個很好的問題」 | 直接回答。 |
| B24 | 結尾硬塞一句哲理或反問 | 讓最後一個可用結論自然結束。 |
| B25 | 反覆用英文式破折號「—」強調 | 依文意改用逗號、句號、括號；必要時可保留破折號。 |

## C. 空泛、行銷或職場套話（[S]／部分 [L]）

| # | Don't | Do：依實際行為或結果表述 |
|---:|---|---|
| C01 | 賦能企業／員工 | 提供什麼權限、工具或訓練 |
| C02 | 打造極致體驗 | 說清楚改善了哪個流程 |
| C03 | 全方位解決方案 | 列出功能範圍與排除項目 |
| C04 | 一站式服務 | 列出在同一平台完成哪些步驟 |
| C05 | 無縫整合 | 說明是否支援 API、同步頻率、限制 |
| C06 | 助力成長／助推轉型 | 說明實際支援的工作 |
| C07 | 解鎖更多可能性 | 指出新增了哪項功能 |
| C08 | 賦予無限可能 | 說明能做什麼，不能做什麼 |
| C09 | 實現價值最大化 | 指出成本、收益或觀察指標 |
| C10 | 提升整體競爭力 | 指出相對哪個對手、哪個指標 |
| C11 | 驅動創新 | 說出已完成的創新或試驗 |
| C12 | 重新定義未來 | 說出具體產品或流程變化 |
| C13 | 賦予品牌生命力 | 指出溝通對象或風格調整 |
| C14 | 形成閉環 | 寫明輸入、處理、回饋和終止條件 |
| C15 | 對齊認知／拉齊顆粒度 | 「確認需求一致／統一驗收條件」 |
| C16 | 抓手／底層邏輯 | 「執行方式／判斷依據／必要條件」 |
| C17 | 沉浸式體驗（無 VR 或具體設計） | 列出真正讓使用者投入的設計 |
| C18 | 打造生態系／生態閉環 | 列出參與者、介接方式、依賴 |
| C19 | 深耕賽道 | 「持續投入某個產品類別／市場」 |
| C20 | 場景化落地 | 「在某個實際情境部署／使用」 |
| C21 | 聚焦核心痛點 | 「解決使用者目前的具體問題」 |
| C22 | 高度靈活、可擴展 | 指出可設定項目、擴充上限或限制 |
| C23 | 強大且直覺的功能 | 描述主要操作步驟及學習成本 |
| C24 | 具備革命性／顛覆性 | 需要量化證據或具體技術突破 |
| C25 | 絕佳／完美／無敵／最強 | 除非有明確測試條件，改用可查證比較 |
| C26 | 絲滑順暢／無感切換 | 寫明延遲、切換中斷或使用感受來源 |
| C27 | 「穩穩地把……接住」等重複抽象隱喻 | 直接描述行為、效果或限制 |

## D. 英文直譯、翻譯腔、冗長句法（[L]／[S]）

| # | Don't | Do | 備註 |
|---:|---|---|---|
| D01 | 對系統進行測試 | 測試系統 | 「進行」多餘 |
| D02 | 進行一個分析 | 分析 | 動詞名詞化 |
| D03 | 做出一個決定 | 決定 | 多餘量詞 |
| D04 | 對使用者提供支持 | 協助使用者／提供支援 | support 視語境 |
| D05 | 這扮演著至關重要的角色 | 這會影響結果／這是必要條件 | 空泛且膨脹 |
| D06 | 這有能力去處理影像 | 這能處理影像 | can be able to 直譯 |
| D07 | 當你完成設定的時候 | 設定完成後 | 時間子句過長 |
| D08 | 在沒有網路的情況下 | 沒有網路時／離線時 | 視文體取捨 |
| D09 | 在……的基礎上進一步…… | 依據……再…… | 刪去墊話 |
| D10 | 作為一個開發者，你需要…… | 開發者需要…… | 英文 as a 直譯 |
| D11 | 從使用者的角度出發來看 | 對使用者來說 | 冗長 |
| D12 | 透過使用某工具來完成作業 | 用某工具完成作業 | 並非禁用「透過」 |
| D13 | 使其能夠達成目的 | 讓它達成目的／藉此完成…… | 其指代不清 |
| D14 | 這將會有助於提升效率 | 這可能減少人工整理時間 | 避免空泛成效 |
| D15 | 你可以選擇去使用…… | 可以使用…… | 刪去「去」 |
| D16 | 被使用者所廣泛接受 | 廣受使用者接受／使用者普遍接受 | 被／所疊加 |
| D17 | 最受歡迎的工具之一 | 有來源才給排名，否則描述用途 | 「之一」可能閃避事實 |
| D18 | 擁有著……功能 | 具有……功能／支援…… | 「著」多餘 |
| D19 | 提供了一個機會讓你去…… | 可以…… | 空泛抽象名詞 |
| D20 | 是一個可以被用來……的方案 | 這個方案可用於…… | 被動句過多 |
| D21 | 這是一個關於……的問題 | 問題是…… | 冗長 |
| D22 | 具有……方面的優勢 | 在……方面較快／較便宜 | 補比較依據 |
| D23 | 在……的領域中 | 在……領域 | 冗字 |
| D24 | 這意味著……（純粹重複前句） | 刪除，或指出實際推論 | 避免假推導 |
| D25 | 它在某種程度上可能帶來一定的幫助 | 具體說明條件；沒依據就標未知 | 多層模糊 |
| D26 | 同時也一併 | 同時／一併，擇一 | 重複 |
| D27 | 目前現階段 | 目前／現階段，擇一 | 重複 |
| D28 | 針對這個議題，我們將…… | 「這個議題……」直接表述 | 「針對」只在明確對象時保留 |
| D29 | 所有使用者都能夠…… | 確認適用範圍，再寫「支援……」 | 避免過度概括 |
| D30 | 這是一個非常獨特的…… | 說明具體差異 | 避免 meaningless intensifier |
